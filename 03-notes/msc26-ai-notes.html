LLM เรียนรู้ยังไง

จดในคาบGenerative
ตอนนี้ LLM เรียนจาก ปิดตัวสุดท้ายไปเรื่อยๆ
ปิดรูปภาพได้ด้วย เช่น พวก App gen รูปใน iPhone หรือแอปรูป

LLM (Large Language Model) อย่าง ChatGPT หรือ Claude ถูก train ด้วยโจทย์ข้อเดียว คือ ปิดคำสุดท้ายไว้ แล้วให้ทายว่าคำต่อไปคืออะไร เรียกว่า next-token prediction โดย token คือหน่วยย่อยของข้อความ ประมาณหนึ่งคำหรือส่วนหนึ่งของคำ

ข้อดีคือไม่ต้องมีคนมานั่งติด label เพราะคำตอบอยู่ในข้อความอยู่แล้ว (เรียกว่า self-supervised learning) จึงเอาข้อความจำนวนมหาศาลมาฝึกได้ เมื่อทายถูกบ่อยพอ โมเดลก็ต้องเข้าใจไวยากรณ์ ความหมาย และความรู้รอบตัวไปด้วย

ตอนใช้งานก็ทำแบบเดียวกัน โมเดลทายคำถัดไปหนึ่งคำ ต่อท้ายเข้าไป แล้วทายคำถัดไปอีก วนแบบนี้จนได้คำตอบทั้งย่อหน้า

ใช้กับรูปภาพได้ด้วย

แนวคิดเดียวกันใช้กับภาพได้ คือปิดบางส่วนของภาพแล้วให้โมเดลวาดส่วนที่หายไปให้กลมกลืน ฟีเจอร์ลบคนหรือวัตถุออกจากรูป และแอปสร้างรูปบนมือถือ ใช้หลักเดียวกันนี้ คือทำให้ภาพหายหรือเสียไปบางส่วน แล้วฝึกโมเดลให้สร้างส่วนนั้นกลับมา

Pre-training → SFT → RLHF

จดในคาบpre-training คือ model ที่มีคน train มาให้แล้ว
RLHF (Reinforcement learning from human feedback) เป็นการให้คะแนนคำตอบของ AI และเอาคะแนนนั้นมา train ในตอบถูกใจคน

LLM ที่เราใช้กันทุกวันผ่านการฝึก 3 ขั้นตามลำดับ

  1. ขั้น 1

    Pretraining

    ฝึกทายคำถัดไปจากข้อความจำนวนมหาศาลที่เก็บจากเว็บและหนังสือ ใช้เวลาและเงินมาก ได้ pre-trained model ที่รู้ภาษาและความรู้ทั่วไป เราไม่ต้อง train ขั้นนี้เอง แต่หยิบโมเดลที่มีคน train มาให้แล้วไปใช้ต่อได้เลย

  2. ขั้น 2

    Instruction Tuning (SFT)

    Supervised Fine-Tuning สอนต่อด้วยตัวอย่างคู่ (instruction, output) เช่น "สรุปข่าวนี้" → บทสรุปที่ดี โมเดลจึงเรียนรู้ว่าต้องทำตามคำสั่ง ไม่ใช่พิมพ์ต่อข้อความไปเรื่อยๆ

  3. ขั้น 3

    Preference Alignment (RLHF)

    ให้โมเดลตอบคำถามเดียวกันหลายแบบ คนเลือกหรือให้คะแนนว่าแบบไหนดีกว่า แล้วเอาคะแนนนั้นไปฝึกให้โมเดลตอบแบบที่คนชอบบ่อยขึ้น

ผลของ RLHF คือโมเดลตอบตรงคำถามขึ้น สุภาพขึ้น และปฏิเสธเรื่องอันตรายได้ ในทางปฏิบัติจะเอาคะแนนจากคนไปฝึกโมเดลอีกตัวที่เรียกว่า reward model ให้ให้คะแนนแทนคนได้ก่อน แล้วใช้ reward model นั้นฝึก LLM ต่อ เพราะคนให้คะแนนทุกคำตอบไม่ทัน

สไลด์ Text · Class 2 · D0, F1
สไลด์เรียกสามขั้นนี้ว่า Pretraining → Instruction Tuning → Preference Alignment และชี้ว่าแต่ละขั้นใช้ข้อมูลคนละชุด ขั้นแรกใช้ข้อความจากเว็บ ขั้นสองใช้ชุดคำสั่งกับคำตอบ ขั้นสามใช้ชุดที่คนบอกว่าคำตอบไหนดีกว่า ตัวอย่างในสไลด์ เช่น ถ้าถามวิธียักยอกเงิน คำตอบที่ปฏิเสธต้องได้คะแนนสูงกว่าคำตอบที่สอนวิธีทำ ข้อมูลขั้นสองไม่ต้องเยอะก็ได้ Alpaca ใช้ตัวอย่างที่โมเดลเขียนให้ 52,000 คู่ ส่วน LIMA ใช้ตัวอย่างที่คนคัดมือแค่ 1,000 คู่ สไลด์ยังเตือนว่าคะแนน RLHF มักมาจากแรงงานค่าแรงต่ำในต่างประเทศ อคติของคนให้คะแนนจึงติดเข้าไปในโมเดลได้

ในโน้ต t คือ token ของข้อความ c คือ context ที่ดึงมาเสริม ส่วน before กับ after คือสิ่งที่ป้อนเข้าโมเดลกับสิ่งที่โมเดลสร้างออกมา t' มีขีดเพราะเป็น token ใหม่ที่โมเดลสร้าง ไม่ใช่ที่เราพิมพ์

ต่อข้อความไปทีละคำ เป็นสิ่งที่ได้จาก pre-training ยังไม่รู้ว่าหน้าที่คือตอบคำถาม

SFT
beforet1t2t3→aftert'1t'2t'3เสี่ยง hallucination

ตอบเป็นคำตอบได้แล้ว แต่ความรู้มาจากที่จำไว้ในโมเดลเท่านั้น

RAG
contextc1c2beforet1t2t3→aftert'1t'2t'3อิงเอกสาร

ค้นเอกสารที่เกี่ยวข้องมาวางไว้หน้าคำถาม แล้วให้โมเดลตอบโดยอ่านจากเอกสารนั้น

Hallucination คืออาการที่โมเดลแต่งคำตอบที่ฟังดูมั่นใจแต่ไม่จริง เกิดเพราะโมเดลถูกฝึกให้ตอบอย่างลื่นไหล ไม่ได้ถูกฝึกให้บอกว่าไม่รู้ ถ้าเรื่องที่ถามไม่อยู่ในความจำ หรือเป็นข้อมูลที่ใหม่กว่าตอน train โมเดลก็ยังเติมคำที่น่าจะเป็นออกมาอยู่ดี

RAG (Retrieval-Augmented Generation) แก้ตรงนี้โดยค้นข้อมูลจริงมาแนบไปกับคำถาม โมเดลจึงตอบจากเอกสารที่เห็นอยู่ตรงหน้า ลด hallucination และบอกแหล่งที่มาได้ เหมาะกับคำถามเรื่องเอกสารภายในองค์กร หรือข้อมูลที่เปลี่ยนบ่อย

สไลด์ Text · Class 2 · F2
สไลด์นิยาม hallucination ว่าเป็นคำตอบที่ไม่ตรงกับข้อเท็จจริงของโลก และยกงานวิจัยที่พบว่าในงานด้านกฎหมาย LLM hallucinate ได้สูงถึง 88% (Dahl et al., 2024) ทางแก้ที่สไลด์เสนอคือ RAG ซึ่งมีสองส่วน คือ retriever ค้นเอกสาร แล้ว generator (LLM) สร้างคำตอบโดยอิงเอกสารนั้น

RAG ค้นหา context ยังไง

จดในคาบcontext คล้ายๆ vector database
top k ตัวที่อยู่ใกล้ที่สุดมาตอบคำถาม ถ้ามีคำถามมาจะถูกแปลงเป็น feature เพื่อมาเทียบใน feature vector DB
  1. เตรียมคลังเอกสาร ตัดเอกสารเป็นชิ้นเล็กๆ (chunk) แปลงแต่ละชิ้นเป็นเวกเตอร์ตัวเลข (เรียกว่า embedding หรือ feature vector) แล้วเก็บไว้ใน vector database
  2. แปลงคำถาม พอมีคำถามเข้ามา ก็แปลงคำถามเป็นเวกเตอร์ด้วยวิธีเดียวกัน
  3. หาตัวที่ใกล้ที่สุด วัดระยะระหว่างเวกเตอร์คำถามกับทุกชิ้นในคลัง (นิยมใช้ cosine similarity) แล้วเลือก k ชิ้นที่ใกล้ที่สุด เรียกว่า top-k
  4. ส่งให้ LLM เอา top-k ไปเป็น context (c1, c2, …) วางไว้หน้าคำถาม แล้วให้ LLM ตอบ

ค่า k เป็นตัวเลือกที่ต้องปรับ ถ้า k น้อยไปอาจพลาดข้อมูลสำคัญ ถ้า k มากไปจะดึงเอกสารที่ไม่เกี่ยวมาปน และโมเดลก็ใช้เอกสารจำนวนมากได้ไม่ดีอยู่แล้ว

สไลด์ Text · Class 2 · F2 "chunks are the new documents"
คลังของ RAG ไม่ได้เก็บเอกสารทั้งก้อน แต่เก็บ chunk ยาวราวไม่กี่ร้อย token ชิ้นเล็กไปจะเสียบริบท (เช่น เหลือแค่ "it was elevated" โดยไม่รู้ว่าอะไรสูง) ชิ้นใหญ่ไปประโยคที่ต้องการจะจมอยู่ในข้อความอื่น วิธีตัดที่นิยมคือตัดที่ย่อหน้าก่อน แล้วตัดที่ประโยค แล้วตัดที่ช่องว่าง โดยให้ชิ้นที่ติดกันซ้อนกันเล็กน้อย ภาษาไทยไม่มีจุดจบประโยคจึงต้องใช้ตัวตัดประโยคภาษาไทย และควรเก็บที่มาของแต่ละชิ้น (เอกสาร หน้า หัวข้อ) ไว้ด้วยเพื่อให้อ้างอิงได้ สไลด์ยังแสดงว่าประสิทธิภาพของ RAG แทบไม่เพิ่มแล้วหลังส่งเอกสารเกิน 10–20 ชิ้น ซึ่งเป็นเหตุผลที่ไม่ควรตั้ง k สูงเกินไป

ต้องคุมอะไรให้เหมือนกันทุก fold

  • y ทุก fold ต้องมีสัดส่วนแต่ละ class เท่าๆ กัน เช่น ปกติ 80% ผิดปกติ 20% เหมือนกันทุก fold วิธีแบ่งแบบนี้เรียกว่า stratified
  • X ที่ซ่อนอยู่ คือข้อมูลประกอบที่ไม่ใช่ input หลักและไม่ใช่ y เช่น เครื่องสแกนที่ใช้ เพศ อายุ ก็ต้องกระจายเท่าๆ กันด้วย ถ้า fold หนึ่งมีแต่ภาพจากเครื่อง 2 คะแนนของ fold นั้นจะสะท้อนความต่างของเครื่องสแกน ไม่ใช่ความเก่งของโมเดล

ขั้นตอน

  1. แยก test set ออกก่อน 1 ก้อน (เช่น 20% ของข้อมูล) ก้อนนี้ห้ามใช้จนถึงขั้นสุดท้าย
  2. ข้อมูลที่เหลือแบ่งเป็น k fold (ในภาพ k = 5) โดยคุมการกระจายของ y และ X ที่ซ่อนอยู่ให้เท่ากัน
  3. แต่ละรอบใช้ 1 fold วัดผล อีก k − 1 fold ใช้ train วนจนทุก fold ได้เป็นชุดวัดผลครบ
  4. เอาคะแนนทุกรอบมาเฉลี่ย ทำแบบนี้กับทุกโมเดลที่จะเทียบ แล้วเลือกตัวที่คะแนนเฉลี่ยดีที่สุด
  5. Train โมเดลที่เลือกด้วยข้อมูลทุก fold รวมกันรอบเดียว แล้ววัดผลกับ test set ที่แยกไว้ ได้ตัวเลขที่จะรายงานจริง

fold ที่ใช้วัดผลในแต่ละรอบ ในโน้ตเรียกว่า test แต่ในตำราและในโค้ดมักเรียกว่า validation เพื่อไม่ให้สับสนกับ test set ก้อนที่แยกไว้ตั้งแต่แรก

ถ้ามองว่าโมเดลลากเส้นแบ่งสองกลุ่ม (แบบ linear คือเส้นตรง) กลุ่มใหญ่มีจำนวนมากกว่าจึงมีน้ำหนักมากกว่า เส้นจะถูกดันเข้าไปหากลุ่มเล็ก จุดของกลุ่มเล็กที่อยู่ใกล้เส้นจึงถูกทายผิดง่าย

3 วิธีในโน้ต

  1. Under-samplingไม่นิยม

    สุ่มตัดกลุ่มใหญ่ทิ้งให้เหลือเท่ากลุ่มเล็ก ข้อเสียคือทิ้งข้อมูลจริงที่เก็บมาอย่างยากลำบาก จาก 950 ภาพอาจเหลือแค่ 50

  2. Over-samplingใช้ได้ แต่ระวัง

    สุ่มก๊อปจุดของกลุ่มเล็กซ้ำ จุดที่ก๊อปอยู่ตำแหน่งเดิม ไม่ได้ข้อมูลใหม่ แต่เพิ่มน้ำหนักให้กลุ่มเล็ก โมเดลจึงสนใจกลุ่มเล็กมากขึ้น เสี่ยงที่โมเดลจะจำจุดเดิมจน overfit

  3. Data Augmentationนิยม

    สร้างตัวอย่างใหม่ที่ไม่ซ้ำของเดิม สำหรับภาพใช้การหมุน พลิก ปรับแสง สำหรับข้อมูลตารางใช้ SMOTE หรือ ADASYN

SMOTE และ ADASYN

SMOTE (Synthetic Minority Over-sampling Technique) สร้างจุดใหม่ของกลุ่มเล็กแทนการก๊อป วิธีคือเลือกจุดกลุ่มเล็กมา 1 จุด หาเพื่อนบ้านในกลุ่มเดียวกันที่ใกล้ที่สุด k ตัว (k nearest neighbors) สุ่มเลือกมา 1 ตัว แล้ววางจุดใหม่ไว้ที่ใดที่หนึ่งบนเส้นตรงระหว่างสองจุดนั้น

xnew = x + λ · (xnn − x),   0 ≤ λ ≤ 1
x คือจุดกลุ่มเล็กที่เลือก, xnn คือเพื่อนบ้านที่สุ่มได้, λ สุ่มระหว่าง 0 ถึง 1 ถ้า λ = 0.5 จุดใหม่จะอยู่กึ่งกลางพอดี

ADASYN (Adaptive Synthetic Sampling) ต่อยอดจาก SMOTE แต่ไม่ได้สร้างเท่ากันทุกจุด จุดกลุ่มเล็กที่มีกลุ่มใหญ่ล้อมอยู่มาก ซึ่งมักอยู่ใกล้เส้นแบ่ง จะได้จุดสังเคราะห์มากกว่า โมเดลจึงได้ฝึกกับบริเวณที่แยกยากมากขึ้น ตรงกับที่จดไว้

เพิ่มเติม ทำ over-sampling, SMOTE หรือ ADASYN กับส่วน train ของแต่ละ fold เท่านั้น ห้ามทำก่อนแบ่ง fold เพราะจุดสังเคราะห์ที่สร้างจากข้อมูลฝั่ง validation จะรั่วไปอยู่ใน train ทำให้คะแนนสูงเกินจริง เป็นกฎเดียวกับที่สไลด์ Image Class 2 สอนเรื่องการคำนวณค่าสถิติจาก train เท่านั้น

Ensemble: รวมหลายโมเดลเป็นหนึ่ง

จดในคาบEnsemble Method
การรวมกัน มี 3 แบบ

1. Bagging จับมาใส่ถุงรวมกันเลย
2. Boosting รวมแบบมีลำดับ
3. Stacking ต่อกันเป็นขั้นๆ

แนวคิดเดียวกับการถามความเห็นหลายคนแทนการถามคนเดียว โมเดลแต่ละตัวพลาดคนละจุด พอรวมกันความผิดพลาดจึงหักล้างกันไปบางส่วน ผลรวมมักดีกว่าโมเดลเดี่ยวที่ดีที่สุด

Bagging

"จับมาใส่ถุงรวมกันเลย"

ชื่อเต็มคือ Bootstrap Aggregating สุ่มข้อมูลแบบหยิบแล้วใส่คืน (bootstrap) ออกมาหลายถุง แต่ละถุง train โมเดลแยกกันพร้อมกัน แล้วรวมผลด้วยการโหวต (classification) หรือเฉลี่ย (regression) ช่วยให้ผลไม่แกว่งตามข้อมูล (ลด variance)

ตัวอย่าง: Random Forest

Boosting

"รวมแบบมีลำดับ"

train ทีละตัวต่อกัน ตัวถัดไปให้ความสำคัญกับข้อที่ตัวก่อนหน้าทายผิด แล้วรวมผลแบบถ่วงน้ำหนัก ตัวที่แม่นกว่าได้น้ำหนักมากกว่า ช่วยให้โมเดลจับรูปแบบที่ซับซ้อนได้ดีขึ้น (ลด bias)

ตัวอย่าง: AdaBoost, Gradient Boosting, XGBoost

Stacking

"ต่อกันเป็นขั้นๆ"

ชั้นแรกใช้โมเดลหลายชนิดที่ต่างกัน ทายผลออกมา แล้วเอาคำทายทั้งหมดเป็น input ให้โมเดลชั้นที่สอง (meta-model) เรียนรู้ว่าควรเชื่อตัวไหนในสถานการณ์ไหน แล้วตัดสินคำตอบสุดท้าย

ตัวอย่าง: kNN + SVM + Decision Tree แล้วใช้ Logistic Regression เป็น meta-model
จำสั้นๆBagging ขนานกันแล้วโหวต · Boosting เรียงกันแก้ข้อผิด · Stacking ซ้อนเป็นชั้น

ภาพดิจิทัลเกิดขึ้นได้อย่างไร

ไล่ตั้งแต่แสงเข้ากล้องจนกลายเป็นตัวเลขใน array เพื่อให้รู้ว่าแต่ละพิกเซลมาจากไหนและมีข้อจำกัดอะไร ก่อนจะเริ่มเตรียมข้อมูลภาพจริงในคาบถัดไป

A1
กล้อง pinhole และเลนส์ เซนเซอร์อย่างเดียวมองไม่เห็นอะไร ทางยาวโฟกัส ขนาดรูรับแสง และเลนส์ เป็นตัวกำหนดว่าภาพจะมีอะไรอยู่บ้าง
A2
เซนเซอร์รับภาพ แสงกลายเป็นอิเล็กตรอนแล้วเป็นตัวเลข (CCD กับ CMOS) และเหตุผลทางฟิสิกส์ที่ทำให้พิกเซลมี noise ค่าตันเพดาน และไม่เป็นเชิงเส้นพอดี
A3
ภาพทางการแพทย์ X-ray อัลตราซาวด์ CT และ MRI ใช้ฟิสิกส์ต่างกันแต่จบที่ array เหมือนกัน ฟิสิกส์เป็นตัวกำหนดว่าความสว่างหมายถึงอะไร และมี noise กับ artifact แบบไหน
A4
Sampling และ quantization พิกเซลคือการสุ่มตัวอย่างจากโลกที่ต่อเนื่อง เก็บด้วยจำนวนบิตที่เลือก เทียบภาพเดียวกันที่ 8, 5, 3 และ 1 บิต และ CT เก็บที่ 12 บิต
A5
Aliasing ย่อภาพแบบทิ้งแถวเว้นแถวจะเกิดลายมัวเร่ที่ไม่มีอยู่จริง วิธีแก้คือเบลอก่อนแล้วค่อยย่อ
B
การเก็บภาพและสี ภาพ grayscale และ RGB ในรูป tensor, ไฟล์ DICOM และ voxel, color space และสิ่งที่กล้องปรับแต่งภาพไปแล้วก่อนเราได้ไฟล์ JPEG
C
การเตรียมภาพขั้นแรก resize และ normalize สองขั้นที่ทุก pipeline ต้องทำ ดูเหมือนง่ายแต่ตัดสินว่าข้อมูลอะไรจะไปถึงโมเดล
จำให้ได้
  • ทุกครั้งที่ resize คือการตัดสินใจ บีบภาพให้เป็น 224×224 ทำให้รูปทรงเพี้ยน เติมขอบให้เป็นสี่เหลี่ยมจัตุรัส (letterbox) รักษารูปทรงแต่เปลืองพิกเซล ภาพทางการแพทย์ต้อง resample ให้ระยะห่าง voxel เป็นมิลลิเมตรเท่ากันก่อน
  • CT เก็บค่าเป็น Hounsfield unit ซึ่งเกิน 255 ไปมาก บีบลง 8 บิตตรงๆ จะมองไม่เห็นเนื้อเยื่อ ต้องเลือก window (center, width) ว่าจะเก็บช่วงความเข้มไหนไว้
  • หารด้วย 255 เปลี่ยนแค่หน่วย ส่วน z-score ย้ายศูนย์กลางของข้อมูลไปที่ศูนย์ซึ่ง optimizer ทำงานได้ดี คำถามที่ทิ้งไว้ให้คาบ 2 คือจะใช้ mean และ std ของใคร ซึ่งเป็นเรื่อง data leakage
  • จดตัวเลขทุกอย่างไว้ ทั้งวิธี interpolation ขนาดภาพ สีขอบ และ spacing คนอื่นต้องสร้าง tensor ชุดเดียวกันได้จาก methods section อย่างเดียว

ต่อจากคาบ 1 เริ่มจากเครื่องมือปรับภาพแบบดั้งเดิม ต่อด้วยการ normalize โดยไม่ให้ข้อมูลรั่ว การใช้โมเดลที่มีคน train มาแล้ว และปิดท้ายด้วย augmentation พร้อมโค้ดจริง

เตรียมข้อมูลให้โมเดล zero-center, scaling, ค่าสถิติแยกตามช่องสี และเหตุผลเชิง gradient ว่าทำไม input ที่เป็นบวกล้วนทำให้ train ช้า
E2

E3
Transfer learning ยืม weight ของโมเดลที่ train มาแล้ว ก็ต้องยืมวิธีเตรียมข้อมูลของมันมาด้วย
F1
Augmentation ความสุ่มที่เปลี่ยนทุก epoch ได้แก่ flip, crop, color jitter, Cutout และ MixUp
F2
Augmentation ภาพการแพทย์ จำลองสิ่งรบกวนจากเครื่องสแกน เช่น ghosting, spike noise, การขยับ, bias field และขอบเขตที่ไม่ควรใช้ MixUp
F3
Pipeline ในโค้ด torchvision v2, Albumentations, Keras preprocessing layers และ MONAI แนวคิดเดียวกันแต่เขียนต่างกัน
จำให้ได้ · 5 ข้อจากสไลด์สรุปท้ายคาบ
  1. filter แบบดั้งเดิมยังไม่ล้าสมัย มันคือพื้นฐานของสิ่งที่ CNN ชั้นแรกเรียนรู้ และของ artifact ทุกแบบที่เราจะต้องไล่แก้
  2. ค่าสถิติทุกตัวที่ใช้เตรียมข้อมูลต้อง fit จากส่วน train แล้วตรึงไว้ ข้อมูลการแพทย์ต้องเพิ่มว่าห้ามข้ามเส้นแบ่งระหว่างคนไข้
  3. pretrained backbone เป็นเหมือนสัญญา ต้องใช้ขนาดภาพ ลำดับช่องสี และค่า normalize แบบที่มันถูก train มา ไม่อย่างนั้นข้อดีของมันจะหายไป
  4. augmentation คือความสุ่มตอน train ตอนทดสอบต้องปิดหรือเฉลี่ยออก การวัดผลต้องใช้ภาพที่ไม่ได้ดัดแปลงเสมอ
  5. pipeline ที่ไม่มีใครรันซ้ำได้ ผลลัพธ์ก็เชื่อถือไม่ได้ seed พารามิเตอร์ และค่าคงที่ต้องอยู่ในโค้ดที่มี version ไม่ใช่อยู่ในความจำ

การเตรียมข้อความแบบดั้งเดิม และเมื่อไหร่ที่มันทำร้ายโมเดล

จาก byte เป็นคำ จากคำเป็นเวกเตอร์ แนวคิดหลักของคาบนี้คือโมเดลข้อความแบบดั้งเดิมรับแต่ตัวเลขที่ได้จากการนับ การเตรียมข้อมูลจึงเป็นตัวกำหนดว่าอะไรจะถูกนับ เช่น "Pain" กับ "pain," นับเป็นคำเดียวกันไหม และคำว่า "not" ถูกเก็บไว้หรือถูกตัดทิ้ง

A0
ทำไมต้องนับคำ Naive Bayes และ logistic regression เห็น bag of words, n-gram language model เห็นจำนวนลำดับคำ, tf-idf และ BM25 เห็นจำนวนแบบถ่วงน้ำหนัก
A1
คำคืออะไร types กับ tokens, จำนวนคำศัพท์ที่โตไม่หยุด, ภาษาที่ไม่มีเว้นวรรค และคำถามว่าใครเขียนข้อความนี้ เมื่อไหร่ เขียนให้ใคร
A2
ข้อความคือ byte Unicode, UTF-8, normalization form, mojibake (ตัวอักษรเพี้ยนเพราะอ่าน encoding ผิด) และการดึงข้อความออกจาก PDF และ HTML
A3
Tokenization ด้วยกฎ regex, รูปแบบของ Penn Treebank, การตัดประโยค และ spaCy ซึ่งยังใช้อยู่ในทุก pipeline รวมถึงการตัดประโยคสำหรับ RAG
A4
Normalization ตัวพิมพ์เล็กใหญ่, stemming, lemmatization และ stop words ซึ่งเคยช่วยมาก แต่ทิ้งข้อมูลที่โมเดลสมัยใหม่ใช้
A5
ภาษาไทย ตัดคำในภาษาที่ไม่มีเว้นวรรคด้วย PyThaiNLP, คำที่ตัดได้หลายแบบ และการ normalize เฉพาะภาษาไทย
B1
จาก token เป็นเวกเตอร์ bag of words และ tf-idf ใน scikit-learn ยังเป็น baseline ที่สร้างได้เร็วที่สุด และยังอยู่ใน retriever แบบ BM25 ที่ป้อนให้ RAG
B2
Augment ข้อความ EDA (สลับ แทน แทรก ลบคำ) และ back-translation (แปลไปภาษาอื่นแล้วแปลกลับ)
C
ข้อความทางคลินิก การจับคำศัพท์ทางการแพทย์, การจับคำปฏิเสธด้วย NegEx, พจนานุกรม UMLS และการลบข้อมูลระบุตัวตนด้วย regex
จำให้ได้
  • ยุคเปลี่ยนแล้ว การแปลงเป็นตัวพิมพ์เล็ก ตัด stop word และ stemming ช่วย tf-idf แต่มักทำร้าย transformer เช่น ตัดคำว่า not ทิ้งแล้วความหมายกลับ สิ่งที่ยังควรทำคือแก้ encoding ตัดข้อความซ้ำ และทำให้ข้อความตอน train กับตอนใช้งานเหมือนกัน หลักง่ายๆ คือเตรียมข้อความให้หน้าตาเหมือนข้อมูลที่โมเดลเคยเห็นตอน pretrain
  • ภาษาไทยมีขั้นทำความสะอาดที่ภาษาอื่นไม่มี เช่น พิมพ์สระเอสองตัวแทนสระแอ, เลขไทยปนเลขอารบิก, วรรณยุกต์ซ้ำ, ไม้ยมกและไปยาลน้อย, ตัวอักษรความกว้างศูนย์ (U+200B) ที่มองไม่เห็นแต่ทำให้ตัดคำผิด และปี พ.ศ. ในวันที่
  • โน้ตแพทย์ไทยเขียนไทยปนอังกฤษและเต็มไปด้วยตัวย่อ (U/D, HT, PTA, Dx) ถ้าตัดคำด้วยพจนานุกรมไทยอย่างเดียว คำอย่าง dyspnea จะถูกหั่นเป็นตัวอักษร โน้ตเดียวกันที่ตัดคำต่างกันก็คือ dataset คนละชุด

Text · Class 2 · LLM Era Preprocessing

การเตรียมข้อความในยุค LLM

ตาม scaling law ผลของ LLM ขึ้นกับสามอย่าง คือขนาดโมเดล พลังประมวลผล และจำนวน token ที่ใช้ train ทีมข้อมูลคุมได้แค่อย่างสุดท้าย คาบนี้จึงตามดู token ตั้งแต่ถูกสร้าง มาจากไหน ถูกคัดอะไรทิ้ง ไปจนถึงชุดข้อมูลขนาดเล็กสำหรับ instruction tuning และการตัด chunk สำหรับ RAG

D0
ทำไมข้อมูลกำหนดสิ่งที่ LLM เรียน scaling laws, ผลของ Chinchilla ที่บอกว่าควรใช้ประมาณ 20 token ต่อ 1 พารามิเตอร์ และการฝึกสามขั้นที่ใช้ข้อมูลสามชุด
D1
Subword tokenization โมเดลเห็นแต่ token ไม่เห็นคำหรือตัวอักษร จึงนับตัว r ใน strawberry ผิด, วิธีทำงานของ BPE และ glitch token ที่ทำให้โมเดลตอบเพี้ยน
D2
ใครจ่ายแพงกว่า tokenizer ที่ train จากข้อความภาษาอังกฤษเป็นหลัก ทำให้ประโยคเดียวกันในภาษาไทยใช้ token มากกว่า 2–4 เท่า ทั้งเปลือง context และค่าใช้จ่าย
E1
ข้อมูล pretraining มาจากไหน Common Crawl, C4, The Pile, หนังสือที่ถูก scrape, คดีลิขสิทธิ์ และสิ่งที่โมเดลจำได้ทั้งข้อความ
E2
ทำความสะอาดระดับเว็บ ตัดข้อมูลซ้ำ 3 ระดับ (ซ้ำตรงทุกตัว ซ้ำแบบคล้ายกัน และใช้โมเดลตัด), กรองคุณภาพด้วยกฎและ classifier, ลบข้อมูลส่วนตัว และผสมข้อมูลหลายแหล่ง
E3
สามการตรวจสอบ ข้อสอบหลุดเข้าไปในข้อมูล train หรือเปล่า (contamination), ข้อความเป็นของใคร และตัวกรองคุณภาพตัดใครทิ้งไปโดยไม่รู้ตัว
F1
Instruction data จาก Alpaca 52,000 คู่ที่โมเดลเขียน ถึง LIMA 1,000 คู่ที่คนคัด, ใครเป็นคนติด label และความเสี่ยงที่โมเดลกินข้อมูลที่โมเดลสร้างจนเสื่อม (model collapse)
F2
เตรียมข้อมูลสำหรับ RAG chunk คือเอกสารแบบใหม่ วิธีตัด แปลงเป็นเวกเตอร์ และทำ index เป็นตัวกำหนดว่าโมเดลจะอ้างอิงอะไรได้บ้าง
F3
ข้อความคลินิกยุคใหม่ บริบทสำคัญกว่าการจับคำ เช่น ประโยคที่มีคำว่า Huntington เป็นทั้งชื่อคน ชื่อโรค และชื่อโรงพยาบาล, การลบข้อมูลระบุตัวตนด้วยโมเดล และ PDPA
จำให้ได้ · 5 ข้อจากสไลด์สรุปท้ายคาบ
  1. tokenizer เป็นส่วนหนึ่งของ dataset มันกำหนดคำศัพท์ ความยาว context และค่าใช้จ่าย และคิดค่าภาษาไทยแพงกว่าภาษาอังกฤษ 2–4 เท่า
  2. การเตรียมข้อมูลระดับเว็บคือการลบออก ตัดซ้ำ 3 ระดับ กรองด้วยกฎที่อ่านเข้าใจได้และ classifier ที่ตรวจสอบแล้ว และจดตัวเลขทุกขั้นไว้
  3. ค่าสถิติที่ใช้คัดข้อมูลและคะแนนที่ใช้เลือกข้อมูลทุกตัวต้อง fit จากข้อมูลฝั่ง train เท่านั้น benchmark และ validation ห้ามมีผลต่อการคัด
  4. ตัวกรองคุณภาพ judge model และข้อมูลสังเคราะห์ ต่างก็มีอคติไปทางใดทางหนึ่ง ก่อนดีใจกับผลที่ดีขึ้นให้เช็กว่าคนกลุ่มไหนหรือภาษาไหนถูกตัดออกไป
  5. สำหรับข้อความคลินิกและภาษาไทย การเตรียมข้อมูลเป็นเรื่องกฎหมายด้วย recall ของการลบข้อมูลส่วนตัว PDPA และที่มาของข้อมูล ต้องเขียนไว้ใน methods คู่กับขนาด chunk และเวอร์ชันของ tokenizer

Machine Learning ทำงานได้ดีต้องมีสองอย่างอะไร

ข้อมูล (Data) ที่มากและหลากหลายพอ กับพลังประมวลผล (Compute) ที่แรงพอจะ train ได้

LLM ถูก pre-train ด้วยโจทย์อะไร

ทายคำถัดไป (next-token prediction) โดยปิดคำสุดท้ายไว้แล้วให้ทาย เลื่อนไปเรื่อยๆ ไม่ต้องมีคนติด label เพราะคำตอบอยู่ในข้อความอยู่แล้ว

RLHF ต่างจาก SFT ยังไง

SFT สอนจากตัวอย่างคำตอบที่คนเขียนให้ ส่วน RLHF ให้คนให้คะแนนคำตอบที่โมเดลสร้างเอง แล้วฝึกให้โมเดลตอบแบบที่ได้คะแนนสูงบ่อยขึ้น

ทำไม RAG ช่วยลด hallucination

เพราะค้นเอกสารจริงที่เกี่ยวข้อง (top-k จาก vector database) มาแนบไปกับคำถาม โมเดลตอบจากเอกสารที่อยู่ตรงหน้า ไม่ต้องพึ่งความจำของตัวเองอย่างเดียว

Agent ต่างจาก RAG ตรงไหน

RAG ค้นครั้งเดียวแล้วตอบ ส่วน Agent ทำหลายขั้น เรียกใช้ tool เอง ดูผล แล้ววนแก้ได้ เช่น เขียนโค้ด → รัน → debug → แก้ จนได้คำตอบ

"X ที่ซ่อนอยู่" คืออะไร และทำไมต้องคุมตอนแบ่ง fold

คือข้อมูลประกอบที่ไม่ใช่ input หลักและไม่ใช่ y เช่น เครื่องสแกน เพศ อายุ ต้องกระจายเท่ากันทุก fold ไม่อย่างนั้นคะแนนแต่ละ fold จะสะท้อนความต่างของกลุ่ม แทนที่จะสะท้อนความเก่งของโมเดล

test set ที่แยกไว้ตั้งแต่แรก ใช้ตอนไหน

ใช้ครั้งเดียวตอนท้าย หลังจากเลือกโมเดลแล้วและ train ใหม่ด้วยข้อมูลทุก fold ระหว่างทำ cross-validation ห้ามแตะ

SMOTE ต่างจาก random over-sampling ยังไง

Over-sampling ก๊อปจุดเดิมซ้ำ ส่วน SMOTE สร้างจุดใหม่บนเส้นระหว่างจุดกลุ่มเล็กกับเพื่อนบ้านที่ใกล้ที่สุด (kNN) จึงได้ข้อมูลที่ไม่ซ้ำของเดิม

Bagging กับ Boosting ต่างกันยังไง

Bagging train หลายตัวพร้อมกันแยกกันแล้วโหวต ช่วยลด variance ส่วน Boosting train ทีละตัวต่อกัน ตัวหลังแก้ข้อผิดของตัวก่อน ช่วยลด bias
